# NEX M03 lighting contract v1

**Status:** `CONTRACT_ONLY_NOT_MODULE_ADMISSION`. This document and the files under `contracts/m03/` define an interface and a prospective ownership map. They do **not** implement M03, create a light, render a shadow, measure performance, or admit any M03 sub-increment.

## Purpose

`lighting.v1.schema.json` describes one bounded lighting observation for the future M03 lighting module: environment intent, the light rig, the shadow budget, explicitly available/unavailable performance metrics, and provenance binding the observation to a Git SHA, Godot version and hardware. It exists so M03 sub-increments can consume/produce a stable interface before any lighting implementation is admitted.

## Invariants

1. **No fabricated measurements.** `MEASURED` requires a finite nonnegative value; `UNAVAILABLE` requires a reason and forbids a value. Zero is a real measurement, never a substitute for missing data.
2. **No FPS claim.** The contract carries frame intervals and render timings, not FPS. A consumer must not derive an FPS claim from synthetic/headless data.
3. **Light identity.** `light_id` values are unique within an observation; `light_type` is `directional`, `omni` or `spot`. A consumer must reject duplicates and dangling references.
4. **Light-type completeness.** `range_m` applies to `omni`/`spot`; `spot_angle_degrees` applies to `spot`; `cascades` applies to `directional`. A consumer must reject a field that contradicts the declared type and a `directional` light with more cascades than `shadow_budget.directional_cascades`.
5. **Shadow budget coherence.** A shadowed light must fit within `max_shadowed_lights`; `directional_cascades` must not exceed `4`; a `spot` angle stays in `(0, 90]` so a shadow map cannot degenerate.
6. **Provenance.** `base_sha` and `head_sha` are lowercase 40-hex Git object IDs; `godot_version`, GPU model and driver are recorded. Evidence URI is optional but required when `measurement_status` is `MEASURED`.
7. **Representation only.** Passing schema validation does not prove lighting quality, shadow correctness or performance; it proves the document is well-formed.

## Validation

```powershell
python -m unittest discover -s tests/contracts -p 'test_*.py' -v
```

The tests use the repository's limited standard-library schema checker. It is not a complete Draft 2020-12 validator; local `$ref` nodes are expanded by the shared `_resolve_refs` helper before evaluation, and unsupported keywords are avoided so the checks remain meaningful in this environment.

## Ownership

`ownership.v1.json` maps prospective M03 write paths to single writers and declares contract consumers. The map is prospective: paths under `nex_modules/lighting/**` do not exist yet, and no module is admitted. Before any future implementation, the Integration Steward must rebind the paths to the actual Git tree and revalidate disjointness. Contract consumers are read-only; shared files (`nex_bench/project.godot`, `nex_bench/hub.gd`, `contracts/m01/**`, `contracts/m02/**`) require the Steward and are never written by a sub-increment.

## Compatibility

A breaking change to a required field, enum, availability semantics or provenance meaning requires a new contract version (`lighting.v2`) and a new ownership revision. Additive optional fields are allowed only after the Steward updates this document and the tests.
