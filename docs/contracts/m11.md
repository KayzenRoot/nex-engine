# NEX M11 asset pipeline contract v1

**Status:** `CONTRACT_ONLY_NOT_MODULE_ADMISSION`. This document and the files under `contracts/m11/` define an interface and a prospective ownership map. They do **not** implement M11, import/cook an asset, verify a license, measure performance, or admit any M11 sub-increment.

## Purpose

`asset_pipeline.v1.schema.json` describes one bounded asset-pipeline observation: asset identity/digest, pipeline stages (`raw` → `imported` → `cooked` → `validated`), SPDX license/attribution/verification, import settings, dependencies, licensing policy, asset/byte budgets, availability-gated performance and provenance.

## Invariants

1. **No fabricated measurements.** `MEASURED` requires a finite nonnegative value; `UNAVAILABLE` requires a reason and forbids a value.
2. **No FPS claim.** The contract carries frame intervals and millisecond timings, not FPS.
3. **Asset identity.** `asset_id` values are unique; `source_sha256` and `artifact_sha256` are lowercase 64-hex.
4. **Stage order.** Stage names are unique per asset; a `pass` at a later stage requires every earlier stage to be `pass` (raw → imported → cooked → validated).
5. **Cooked artifact.** When `policy.require_cooked_artifact` is true, the asset must have a `cooked` stage with `pass` and an `artifact_sha256`.
6. **Licensing.** A `rejected` license is invalid. When `require_verified_license` is true, verification must be `verified`. When `allow_unverified` is false, `unverified` is invalid. `spdx_id` must be in `allowed_spdx_ids`. When `require_attribution` is true, `attribution` must be non-empty.
7. **Dependencies.** Every dependency references an existing asset, never itself, and the dependency graph is acyclic.
8. **Budget.** Asset count, total cooked bytes, texture cooked bytes and unverified licenses must each fit their budget.
9. **Provenance.** `base_sha`/`head_sha` are lowercase 40-hex Git object IDs; evidence URI is required when `measurement_status` is `MEASURED`.
10. **Representation only.** Passing schema validation does not prove import/cook correctness, license clearance or performance.

## Validation

```powershell
python -m unittest discover -s tests/contracts -p 'test_*.py' -v
```

The tests use the repository's limited standard-library schema checker with local `$ref` expansion; unsupported keywords are avoided.

## Ownership

`ownership.v1.json` maps prospective M11 write paths (`nex_modules/assets/**`) to single writers. The paths do not exist yet and no module is admitted. Contract consumers are read-only.

## Compatibility

A breaking change to a required field, enum, availability semantics or provenance meaning requires `asset_pipeline.v2` and a new ownership revision. Additive optional fields are allowed only after the Steward updates this document and the tests.
